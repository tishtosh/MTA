Search dropdown → Bus / Metro / Commuter summaries

Four directions for the route sections, shown both inside the dropdown and as a full main page. Data is the real line/route set per city (DC, Boston, London, NYC); the city switch below updates every option at once.

1 · Accordion (current) 2 · Route grid 3 · Tabs + detail 4 · Summary cards City examples
Recommendation: use 2 · Route grid inside the dropdown (fits NYC's 10+ commuter branches without scrolling) and 3 · Tabs + detail as the main page, where the right pane can show stops and next departures.

1 · Accordion rows

baseline

The current shape: one section per category, each row = badge + route name + a small meta line. Zero new concepts; works best when a city has few lines.

  • Familiar, accessible
  • Route name has room
  • Tall with many lines (NYC commuter)
  • Scanning colors is slow

As a main page

2 · Route grid

recommended for the dropdown

Each section becomes a compact grid of bullets/pills; the section header keeps the name and count. Dense enough for 10–15 routes and color-first, like a departure board.

  • No scrolling for long line lists
  • Color scanning
  • Names need a tooltip/title
  • Long names wrap in rectangles
In the dropdown
As a main page

3 · Tabs + detail

recommended for the main page

A segmented control picks Bus / Metro / Commuter; the left list selects a route and the right pane shows stops and next departures. In the dropdown it collapses to the same list without the detail pane.

  • One category visible at a time
  • Room for stops + ETAs
  • Search by stop or line
  • Needs a second pane on desktop
  • Tabs hide the other modes
In the dropdown
As a main page

4 · Summary cards

overview

Three cards (Bus / Metro / Commuter) show counts and the top routes; opening a card goes to the route grid or tabs. Good landing page, too coarse for the dropdown itself.

  • Instant category overview
  • Handles missing sections gracefully
  • Two taps to a route
  • Wastes space with 3 routes
